# Term Frequency Analyzer

[![Python 3.10+](https://img.shields.io/badge/python-3.10+-blue.svg)](https://www.python.org/downloads/)
[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](https://opensource.org/licenses/MIT)
[![NLP](https://img.shields.io/badge/NLP-Natasha%20%2B%20pymorphy3-orange.svg)](https://github.com/natasha/natasha)

NLP-инструмент для морфологического анализа частотности терминов в текстовых корпусах с построением динамики по тематическим сегментам.

Проект разработан и апробирован на корпусе учебников биологии 5–11 классов (~350 000 слов, 1200+ терминов), однако архитектура не привязана к предметной области и применима к любому русскоязычному корпусу.

---

## Описание

Инструмент решает задачу автоматического поиска терминов (в том числе многословных) в текстовых документах с учётом морфологии русского языка: один термин из словаря находит все свои словоформы в тексте.

Основные сценарии применения:

- Корпусная лингвистика: анализ терминологической насыщенности текстов
- Учебное книгоиздание: оценка динамики введения понятий по годам обучения
- Контент-анализ: отслеживание частотности ключевых понятий в корпусе

### Основные возможности

- Поиск терминов с учётом морфологии — одна запись в словаре покрывает все словоформы
- Поддержка многословных терминов (н-граммы): "клеточная мембрана", "аппарат Гольджи"
- Нормированная частота (ipm — instances per million words)
- Динамика по корпусам: таблица частотности по каждому сегменту
- Подсветка найденных терминов в DOCX-документах (красный цвет)
- Логирование контекстов: сохранение примеров употребления с окружением в CSV
- Двухслойная лемматизация: Natasha для скорости, pymorphy3 для точности
- Распознавание и пропуск имён собственных (NER)
- Корректная обработка дефисных конструкций
- Пакетная обработка нескольких документов

## Технологический стек

| Задача | Инструмент | Версия |
|--------|-----------|--------|
| Сегментация и POS-tagging | [Natasha](https://github.com/natasha/natasha) | 1.6.0+ |
| Коррекция лемматизации | [pymorphy3](https://github.com/no-plagiarism/pymorphy3) | 1.0.0+ |
| Токенизация, стоп-слова | [NLTK](https://www.nltk.org/) | 3.8.0+ |
| Обработка данных | pandas, numpy | 2.0.0+ |
| Работа с DOCX | python-docx | 0.8.11+ |
| Работа с Excel | openpyxl | 3.1.0+ |

**Ключевое архитектурное решение:** двухслойная лемматизация. Natasha даёт контекстно-зависимый анализ, pymorphy3 исправляет системные ошибки на кратких прилагательных, причастиях и глаголах совершенного вида. Это обеспечивает точность поиска без ручной правки словаря.

### 1. Подготовка данных

Разместите файлы:

```
data/
  terms_dictionary.xlsx    # один столбец с терминами, без заголовка

textbooks/
  segment_1.docx
  segment_2.docx
  ...
```

Формат словаря терминов — один столбец, одна строка на термин:

| (без заголовка) |
|-----------------|
| клетка          |
| биологическая эволюция |
| аппарат Гольджи |
| ДНК             |

Многословные термины записываются в исходной форме — нормализация выполняется автоматически.

Откройте `config.py` и укажите пути:

```python

# Директория с входными документами
TEXTBOOKS_DIR = PROJECT_ROOT / "textbooks"

# Соответствие: ключ сегмента -> файл
GRADE_DOCX = {
    5:  TEXTBOOKS_DIR / "segment_5.docx",
    6:  TEXTBOOKS_DIR / "segment_6.docx",
    # ...
}
```

Проверьте конфигурацию:

## Формат выходных данных

### term_dynamics.xlsx

Сводная таблица частотности по всем сегментам корпуса.

| Термин | КВ 5 | КВ 6 | ... | НЧ 5 | НЧ 6 | ... |
|--------|------|------|-----|------|------|-----|
| клетка | 245 | 312 | ... | 6835.2 | 9294.1 | ... |
| эволюция | 12 | 34 | ... | 335.0 | 1012.8 | ... |

- **КВ N** — количество вхождений в сегменте N
- **НЧ N** — нормированная частота в сегменте N (instances per million words)

### context_logs/segment_N_contexts.csv

Примеры употребления каждого термина с контекстом.

| Grade | Doc | Term | Pattern | Match# | Surface | Context |
|-------|-----|------|---------|--------|---------|---------|
| 5 | segment_5.docx | клетка | клетка | 1 | клетки | все организмы состоят из клеток которые |
| 5 | segment_5.docx | биологическая эволюция | биологический эволюция | 1 | биологической эволюции | в ходе биологической эволюции сформировались |

- **Surface** — как термин выглядит в исходном тексте
- **Context** — окно ±6 токенов вокруг совпадения
- **Pattern** — нормализованный паттерн лемм, по которому велся поиск

### annotated_textbooks/

Копии входных документов с терминами, выделенными красным цветом.
Подсветка применяется к абзацам и ячейкам таблиц.

## Алгоритм работы

### Нормализация термина из словаря

```
Исходник: "биологическая эволюция"
    remove_accents()        удаление диакритики
    replace_letters()       латиница -> кириллица (A->А, O->О и др.)
    tokens_with_punct()     сегментация (Natasha Segmenter)
    lemmatize()             лемматизация (Natasha + коррекция pymorphy3)
Паттерн: "биологический эволюция"
```

### Поиск паттерна в тексте

```
Текст: "Биологическая эволюция — основа..."
    tokens_with_punct()     токены с позициями [start, end)
    build_indexed_words()   только словарные токены
    для каждой позиции i:
        взять k токенов начиная с i
        проверить смежность (соседние tok_idx)
        сравнить паттерн лемм с искомым
        сохранить символьные позиции совпадения
```

### Подсветка в DOCX

```
для каждого абзаца:
    compute_highlight_spans()   символьные интервалы [start, end)
    merge_spans()               объединение перекрывающихся интервалов
    apply_highlights()          перезапись runs с RGBColor(255, 0, 0)
```

### Двухслойная лемматизация

Natasha иногда возвращает краткие формы вместо полных:

```
"рассмотренный" -> Natasha: "рассмотренный" (PRTS, краткое)
                -> pymorphy3: "рассматривать" (VERB, impf, полная)
```

Коррекция применяется в трёх случаях:

- `ADJS` (краткое прилагательное) -> `ADJF` (полное)
- `PRTS` (краткое причастие) -> `PRTF` (полное) или инфинитив
- `VERB` (совершенный вид) -> поиск варианта `impf` (несовершенный)

## Параметры конфигурации

Все параметры редактируются в `config.py`:

```python
# Допускать пунктуацию между словами фразы при поиске
# False: "клеточная мембрана" — слова должны идти строго подряд
# True:  "клеточная, мембрана" — допускается пунктуация между словами
ALLOW_PUNCT_BETWEEN = False

# Не считать унигаммы рядом с дефисом
# Полезно чтобы "кислород" в "кислород-зависимый" не засчитывался отдельно
DISALLOW_HYPHEN_ADJACENT_FOR_UNIGRAMS = False

# Размер окна контекста (токенов слева и справа от совпадения)
CONTEXT_WINDOW = 6

# Максимум контекстов на один термин в логах
MAX_CONTEXTS_PER_TERM = 20

# Знаменатель нормировки
NORM_PER = 1_000_000

# Логировать контексты для всех терминов
DEBUG_ALL_TERMS = True

# Или только для конкретных терминов (если DEBUG_ALL_TERMS = False)
DEBUG_TERMS = ["клетка", "эволюция"]
```

## Производительность

| Задача | Время | Объём |
|--------|-------|-------|
| Инициализация моделей | 30-60 сек | однократно |
| Нормализация словаря (1200 терминов) | 5-10 мин | однократно |
| Анализ одного документа | 2-5 мин | ~50 000 слов |
| Подсветка одного документа | 3-7 мин | ~50 000 слов |

Тестировалось на Intel Core i5, 16 GB RAM.

Узкое место — инициализация Natasha (NewsEmbedding) и нормализация каждого термина через полный пайплайн лемматизации. После инициализации скорость обработки текста — ~500-1000 токенов в секунду.

## Известные ограничения

- Латинские термины без явного добавления в словарь не обнаруживаются
- NER может пропустить редкие или нестандартно написанные имена собственные
- Омонимы разрешаются по наивысшей вероятности pymorphy3 без учёта расширенного контекста
- Скорость обработки ограничена нейросетевыми моделями Natasha (нет GPU-ускорения)
- Требуется Python 3.10+

## Troubleshooting

### ModuleNotFoundError: No module named pkg_resources

```bash
pip install --upgrade setuptools
```

Модуль `src/patch_pkg_resources.py` автоматически создаёт заглушку для `pkg_resources`, если он недоступен. Патч применяется при первом импорте `preprocessing.py`.

### Термин есть в тексте, но не находится

```bash
python main.py --debug-term "термин" --debug-text "текст с термином"
```

Частые причины:

- Термин после лемматизации даёт пустой паттерн (попал под фильтры)
- Между словами фразы есть знак препинания — установите `ALLOW_PUNCT_BETWEEN = True`
- Лемма попала в `replacements.txt` и заменилась на другое слово
- Слово окружено дефисами — установите `DISALLOW_HYPHEN_ADJACENT_FOR_UNIGRAMS = False`

### FileNotFoundError при запуске

Проверьте конфигурацию:

```bash
python config.py
```

Все предупреждения `⚠` указывают на отсутствующие файлы или директории.
