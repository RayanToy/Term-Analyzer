# Поиск единиц культурного кода в учебниках истории

Ищет ~1170 наименований объектов культурного кода (`Список наименований объектов КК.xlsx`)
в 13 учебниках истории Мединского и выдаёт результат в формате прошлой работы по
фразеологизмам: сводный Excel, Excel по каждой книге и docx с подсветкой найденного.

## Запуск

```
conda run -n kk python main.py
```

| ключ | что делает |
|---|---|
| `--lemmatizer {pymorphy,natasha,both}` | вариант морфологии; по умолчанию `both` со сравнительным отчётом |
| `--primary {pymorphy,natasha}` | по какому бэкенду собираются основные отчёты (по умолчанию `pymorphy`) |
| `--only 05_01` | обработать только учебники, чьё имя содержит подстроку (можно повторять) |
| `--no-highlight` | не создавать docx с подсветкой |
| `--no-pdf` | не разбирать PDF |
| `--debug-unit "Крейсер «Аврора»"` | показать, во что разворачивается наименование |

Тесты: `conda run -n kk python -m pytest tests -q` (52 теста, прогоняются на обоих бэкендах).

Сверка PDF с docx: `conda run -n kk python tools/check_pdf_vs_docx.py`.

└── _Подсветка\<раздел>\<учебник>.docx

Подсветка: **красный** — уверенное вхождение, **оранжевый** — спорное, которое правила
отклонили. Форматирование исходного документа сохраняется.

## Морфология

Вся лемматизация — **pymorphy3**. pymorphy2 в проекте не используется и не установлен:
natasha тянет его только ради `MorphVocab`, который здесь не нужен, поэтому
`src/natasha_loader.py` подставляет заглушку и грузит из natasha только теггер частей речи.

Два бэкенда за общим интерфейсом (`src/lemmatizers.py`):

* **pymorphy** — razdel + pymorphy3, поиск идёт по **всем** возможным леммам словоформы;
* **natasha** — контекстный `NewsMorphTagger` определяет часть речи, ею отсеиваются
  неподходящие разборы pymorphy3 («Стали делать сталь» — первое слово только глагол).

По итогам прогона на всём корпусе разница между бэкендами — единицы вхождений из 34 тысяч,
при этом natasha примерно в 10 раз медленнее. Подробности — в `_сравнение_лемматизаторов.xlsx`.

## Правила поиска

Единицы разворачиваются в лемма-паттерны. Для составных названий дополнительно
порождаются варианты: без скобочного пояснения, по содержимому кавычек и без родового
слова. `Царь-подлодка (АПЛ проекта 941 «Акула»)` ищется ещё и как `Царь-подлодка`, и как
`Акула`; `Крепость Порт-Артур` — как `Порт-Артур` (в учебнике пишут «атаковали
Порт-Артур», а не «атаковали крепость Порт-Артур»). Родовое слово не отбрасывается там,
где заглавная — часть цельного названия: `Золотые ворота в Киеве` (родовая часть кончается
предлогом), `Успенский собор Московского Кремля` (дальше идёт родительный падеж, то есть
определение, а не имя).

Между словами многословной единицы допускается пунктуация, но не другие слова:
«Не имей сто рублей, а имей сто друзей» находится вместе с запятой.

### Регистр

В исходном списке **все** наименования записаны с заглавной буквы, поэтому регистр сам по
себе ничего не значит. Правило регистра применяется только там, где есть подтверждение:

* **однословные имена собственные** — помета словаря (Geox/Name/Surn/Patr/Orgn/Trad) либо
  ручной список `data/proper_units.txt` (там «Победа», «Союз», «Москвич», «ГАЗ», «Мы»,
  «Идиот» — у них пометы нет, а имя собственное это);
* **многословные названия произведений** из групп «Худ. лит.», «Кино, театр», «ИЗО»
  (`config.TITLE_GROUPS`) — нужна заглавная в первом слове либо кавычки, иначе «Война и мир»
  ловит «вопросы о войне и мире».

«Баня», «Василёк», «Храм», «Царь», «Медведь», пословицы и фольклор ищутся **без учёта
регистра** — это нарицательные, и в тексте они пишутся со строчной. В «природно
нарицательных» группах (`config.COMMON_NOUN_GROUPS` — быт, флора, фауна, кухня, огород,
соц. слои, единицы измерения…) помете словаря не верим вовсе: у «Поле», «Лен», «Орел»
(птица) в OpenCorpora есть разбор Geox, из-за которого они переставали находиться.
`data/proper_units.txt` сильнее этого исключения.

### Фамилии против нарицательных

Русские фамилии совпадают с родительным падежом множественного числа обычных слов:
«Соловьёв» — это и фамилия, и форма слова «соловей», «Пирогов» — «пирог», «Воронов» —
«ворон», «Муравьёв» — «муравей», «Лены» — и «лён», и река Лена. Поскольку поиск идёт по
всем возможным леммам, историк С. Соловьёв засчитывался как птица.

Вхождение отбрасывается, если слово написано с заглавной буквы **в середине предложения**,
у него есть разбор как имени собственного, но лемма единицы через этот разбор не
получается. У «Авроры» лемма «аврора» приходит как раз из разбора `Name`, поэтому крейсер
не страдает; у «Победа» и «АК-47» разбора как имени собственного нет вовсе, и правило
молчит. Строчные написания не затрагиваются — «соловьёв» действительно может быть птицами.

Отдельно учитываются инициалы и сокращения: без этого «Историк С. Соловьёв» и
«Худ. И. Репин» выглядели как начало предложения, где заглавная буква ничего не значит
(`analyzer.ABBREVIATIONS`).

### Спорные вхождения

Заглавная буква бывает вынужденной — начало предложения, заголовок (в том числе
нумерованный, «4 Храмы.»), капслок. Такие случаи решает каскад, первое сработавшее правило
побеждает:

1. у словоформы вообще нет нарицательного прочтения (только Geox/Name/…) → засчитать;
   для омонимов вроде «Орёл» правило молчит: помета Geox стоит и у города, и у птицы;
2. слово в кавычках → засчитать;
3. рядом (±3 словарных токена) родовое слово из `data/generic_heads.txt` — крейсер,
   ледокол, город, ракета, роман, опера… → засчитать;
4. у этой же единицы в этом же учебнике есть уверенное вхождение → засчитать;
5. иначе → отклонить.

Ничего не теряется: все спорные попадают на лист «Спорные» с контекстом и причиной решения,
а в docx помечаются оранжевым. Оба словаря в `data/` можно править — изменения подхватятся
при следующем прогоне.

### Возможные пропуски

Основной поиск требует, чтобы слова единицы шли подряд и в том же порядке. В учебнике
название нередко записано иначе: «Софийского собора в **Великом** Новгороде», «в Киев
служили Золотые ворота», «стояли **Детинец** Новгородский кремль». Автоматически
засчитывать такое нельзя — тот же приём находит и явный мусор («судьбу определяют три
сестры» на «Три сестры»). Поэтому многословные единицы с нулём вхождений, все слова
которых всё же встречаются в одном окне, собираются на лист **«Возможные пропуски»**
с контекстом (`src/review.py`).

Единицы, которые в тексте нашлись, но были отсеяны правилами регистра, сюда не попадают —
они уже описаны на листе «Спорные» с причиной.

Список проверен вручную; вердикт по каждому случаю лежит в `data/review_verdicts.txt` и
выводится на листе в колонках «Проверено вручную» и «Комментарий»: `пропуск` — объект
действительно назван, но иначе; `пограничное` — объект назван, а словосочетания нет;
`ложное` — совпадение случайное.

Вердикты из `config.REVIEW_COUNTED_VERDICTS` (по умолчанию только `пропуск`) **добавляются
в подсчёт** и видны в отдельной колонке **«в т.ч. добавлено вручную»** — она есть и в
книжных файлах, и в сводном, и на листе «Сводка по учебникам». В листе «Контексты» у таких
строк статус «добавлено по ручной проверке (в docx не подсвечено)».

Важное следствие: у этих вхождений **нет подсветки** в docx — дословно фразы в тексте нет,
выделять нечего. Поэтому «Количество» может превышать число выделенных мест ровно на
значение колонки «в т.ч. добавлено вручную»; `tools/check_totals.py` проверяет, что эта
колонка сходится между книжными файлами и сводным. Чтобы учитывать и пограничные случаи,
достаточно добавить `"пограничное"` в `REVIEW_COUNTED_VERDICTS`.

## Источники текста

Считаем по `.docx`: он же нужен для подсветки, а `.txt` — его же текст (пословный diff
показал различия только в номерах автосписков). Два файла 9 класса «Всеобщей истории»
идентичны, второй пропускается (`config.SKIP_FILES`).

PDF содержит 7–40 тыс. слов на учебник, которых в `.docx` нет: подписи к иллюстрациям,
вопросы к ним, титул, колонтитулы. Эта «добавка» выделяется пословным сравнением
(`src/pdfsource.py`; повторяющиеся колонтитулы схлопываются).

При `config.COUNT_PDF_EXTRA = True` (по умолчанию) её вхождения **складываются** с
основными числами того же учебника и помечены колонкой **«в т.ч. из PDF»** — она есть в
книжных файлах, в сводном и на листе «Сводка по учебникам». Разбор каждого вхождения с
контекстом остаётся на листе **«Только в PDF»**; колонка «Есть ли в .docx» показывает, что
без PDF было бы упущено совсем.

Оговорка: текст из PDF извлекается с искажениями (сбитый порядок колонок, разорванные
переносом слова, служебные токены), поэтому часть этих вхождений — мусор. Подсветки у них
нет: самого текста подписи в `.docx` не существует. Чтобы считать только по `.docx`,
достаточно поставить `COUNT_PDF_EXTRA = False`.

## Проверки

| инструмент | что проверяет |
|---|---|
| `tools/check_totals.py` | сумма по книжным файлам = «Итого» сводного; «Матрица» сходится по строкам; листы групп в сумме дают «Все единицы» |
| `tools/check_highlight.py` | текст подсвеченных docx совпадает с исходным символ в символ, форматирование каждого символа не изменилось |
| `tools/check_pdf_vs_docx.py` | полнота `.docx` относительно PDF; результат в `_лог_сверки_PDF.txt` |
| `tests/test_matching.py` | поведение поиска на реальных случаях, оба бэкенда |

```

  proper_units.txt   имена собственные, не помеченные словарём

  text_utils.py      нормализация (латинские гомоглифы, ударения, ё→е)
  natasha_loader.py  загрузка natasha в обход pymorphy2
  lemmatizers.py     PymorphyBackend | NatashaBackend
  units.py           разбор Excel со списком, группы, варианты названий
  analyzer.py        бор лемма-паттернов, поиск, контексты
  disambiguation.py  правила регистра и разрешение спорных
  docio.py           чтение docx (абзацы + run'ы)
  highlighter.py     подсветка с сохранением форматирования

  report.py          сборка Excel

  check_pdf_vs_docx.py
tests/test_matching.py
```

## Что взято из прежних репозиториев и что в нём исправлено

Основа — **Term-Analyzer** (многословные термины, лемма-паттерны, красная подсветка docx):
взяты `count_patterns_strict`, `_words_are_adjacent`, `_build_context`, `merge_spans`,
`compute_highlight_spans`, `annotate_docx` и нормализация текста из `TextPreprocessor`.
Из **Russian-Lexicon-Analyzer** — приём подсветки красным и разбиение на
`lexicon / matcher / highlighter`. **Lexical-Core-Builder** и
**Ru-Text-Classification-Pipeline** к этой задаче не относятся.

Что пришлось поправить:

| # | было | почему ломало | стало |
|---|---|---|---|
| 1 | `_BANNED_POS` выбрасывал PRON/NUM/ADP/CONJ/PART | рассыпались пословицы и названия с предлогами | словарным считается любой токен с буквой или цифрой |
| 2 | `ALPHA_RE` требовал букву | терялись «АК-47», «Ту-144», «Восток-1», «58-пушечный» | цифры допускаются |
| 3 | `disallow_hyphen_adjacent_for_unigrams=True` | убивало «Ванька-встанька», «Царь-бомба», «Соколов-Микитов» | отключено |
| 4 | `allow_punct_between=False` | «Семь раз отмерь, один отрежь» не находилось | включено |
| 5 | поиск по одной, самой вероятной лемме | pymorphy для «Авроры» даёт «аврор» — крейсер «Аврора» терялся | бор по **всем** леммам словоформы |
| 6 | `apply_highlights_to_paragraph` сносил все run'ы абзаца | в учебнике терялись жирный, курсив, кегль, стиль заголовка | run режется по границам совпадения, `rPr` копируется |
| 7 | подсчёт и подсветка — два независимых прохода | числа в Excel и в docx могли разойтись | один проход даёт и то и другое |
| 8 | морфология жёстко зашита на natasha | нельзя было сравнить с более лёгким вариантом | два бэкенда за общим интерфейсом + отчёт сравнения |

| 10 | разбор Excel не учитывал ячейки из пробелов | в исходном файле есть `' '` в колонках A/B — группа «съезжала» | такие ячейки считаются пустыми |
